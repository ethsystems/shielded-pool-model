# Claim 1, rule by rule

**Claim 1 (on-chain safety), the target.** Nobody can steal, mint or double-spend pool funds, whatever
client they submit from. It is a target, not yet an established theorem about a deployment. The Lean model
proves conservation, no minting, no double spending and witness-key authorization under its premises
(LEDGER row 1). Applying that to a deployment needs C1, the assumptions at the end, every rule below, and X3:
a complete argument that every accepted contract execution matches the model's guards and post-states, from
the empty pool. Adversarial clients are in scope; a user's own leaked key or malicious client is not (A7).

**How to read this table.** Rows are of four kinds: model guards (`LeanShieldedPool/Pool/Tx.lean`: deposit
106-110, transfer 141-160, withdraw 186-193), values the model builds by construction (commitments and
nullifiers as hash images), state updates (T12, T13, W6, X2), and implementation obligations the model does
not state (D6, S1-S3, X1, W10, G1; CLAUSEMAP simplifications 7, 15 and the omitted proof system). Each row
names the enforcing layer, the evidence today and its status. Trusted components common to many rows are
A11; a row's "Proved" is always within A11.

See [Why not green](#why-not-green) for each assumed row's blocker and next step.

Status words:
- **Proved:** machine-checked in full within the named formal domain (a Lean proof over the extracted
  circuit or model, a complete symbolic check of loop-free code, or an exact rebuild). It never means
  deployment safety by itself.
- **Proved\*:** the Kontrol property is machine-checked over its symbolic domain, and a written EVM gas argument
  (GAS-LEMMA, Lean-checked arithmetic) places every transaction under the EIP-7825 cap (2^24 gas) inside that domain.
  All other N5/N5b premises remain: canonical ABI calls, pins, mocks, keccak lemmas, gas not modelled. Not deployment
  safety. \* valid for transactions under the EIP-7825 gas cap (2^24); the below-2^30 conclusion survives any
  transaction gas limit under 4 x 2^30 gas. Canonical ABI layout and the N5/N5b scope remain required (Fable judge).
- **Partly proved:** machine checks cover only the stated parts of the rule.
- **Counting rule (Council C2):** a row counts green when its status starts with "Proved" or "Proved*". A row enforced
  by two layers (circuit and contract) counts green only when both layers are proved or Proved*. "Bounded" counts
  as partly proved.
- **Bounded:** machine-checked within stated bounds (small trees, one reached state, a hand copy).
- **Assumed (GROUP):** (since 2026-10-02, writeup plan v3) the full rule retains an explicitly assumed gap. Before the
  first semicolon, name its primary groups and gap. After it, summarize existing evidence as proved, bounded, or read.
  Every subclaim retains the limits in its evidence cell and cited judge. These tags do not replace the full premise
  list. Reclassification adds no machine evidence. Count the whole row as assumed, even if a subclaim is proved
  (Astra judge).
- **Read:** source reading and tests only.
- **Open:** not checked yet. **Running:** a worker is on it now.
- **Assumed:** a named assumption; **Condition:** a deployment requirement.

**N5 and N5b scope (Kontrol, 2026-10-01, Astra judge).** N5/N5b use canonical ABI calls, zero value, symbolic
caller and pool storage, and earlier-guard premises. Stock deposit/transfer byte lengths are 0..2^30. Patched W1/W6/W7/W8c
cover proof lengths below 2^64 (the patch deletes one KEVM encoding assumption, `abi.md:456`). Pool slots 108/109 pin
the mock verifier/registry; the reentrancy slot pins 1. Code stays fixed; registry storage is symbolic. KEVM keccak
assumptions and environment bounds remain; gas computation is disabled. Exact selectors establish rejection and
exclude the verifier marker. Retained-state preservation follows from rollback. All 13 stock controls fail; patched
M_W7 also fails.

**Byte-length envelope (D1, Fable judge).** Under EIP-7825 and EIP-7623, transaction data is at most 1,675,621 bytes, and
the memory charge bounds each internal-call input and each backed decoded byte argument by 2,941,344 bytes, below 2^30.
A research-record note (2026-10-01) gives the written argument; a Lean file checks its arithmetic.
A gas-starved call can fail before its guard; gas stays unmodelled in N5/N5b.

### What can never be green, and why

An unconditional deployment claim cannot follow from these proofs. Arbitrary tokens need not obey A10, including exact amounts, insufficient-balance rejection and no fees, rebases or outside debits. Additions and upgrades must preserve those properties. A1 assumes no commitment or derived-key collisions in the history. Cryptographic hardness and secret keys remain premises. Trusted tools remain under A11, including patched Lampe, KEVM/Kontrol, Halmos and the compilation chain.

Deployment facts need external checks: pinned runtime code, addresses, library links, verifier slot order, build settings, mocks disabled and no verifier swaps. C1 also requires transaction gas below 4 x 2^30 for Proved*. No deployment beyond the local test chain exists today.

### What is possible but expensive

X3 can connect actual execution to the model. It needs universal posts, circuit interpretation, extraction, tree correspondence, token effects and rollback. Events remain open too. The conditional composition preserves money conclusions without RootsNonzero. Both routes need OwnerCallbackFree and CryptoHyp; D3 needs TreeHyp, while PATHLOCAL needs PathFacts and PathTreeHyp. Budget days to weeks; bounded component checks cannot supply those universal premises.
