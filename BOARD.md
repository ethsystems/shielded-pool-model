# Claim 1, rule by rule

This is the obligations board for claim 1 that the writeup cites. It lists the 36 rules a
deployed pool must meet for the model's money theorems to describe it, the layer that enforces
each rule, the evidence, and a status. It is a status document: people chose the status words
and the counting rule, after cross-family reviews, and a status is not itself a machine result.
The rule texts, enforcing layers and status cells are those of the board as it stood on
2026-10-13. Each evidence cell names the check in this repository that backs the row, by package
and by suite or theorem, with the command that runs it. Where no package covers a piece of
evidence, the cell says so and gives the date it was measured. Each package's README states the
exact scope of its checks. Six packages (`deployment/`, `privacy-games/`, `refinement/`,
`client-verus/`, `contract-halmos/`, `contract-kontrol/`) record their last run in a RESULT.md;
the other four record it in their README.

**Claim 1 (on-chain safety), the target.** Nobody can steal, mint or double-spend pool funds, whatever
client they submit from. It is a target, not yet an established theorem about a deployment. The Lean model
proves conservation, no minting, no double spending and witness-key authorization under its premises
(the core claim, [CLAIMS.md](CLAIMS.md) rows 1 to 9). Applying that to a deployment needs C1, the
assumptions at the end, every rule below, and X3: a complete argument that every accepted contract
execution matches the model's guards and post-states, from the empty pool. Adversarial clients are in
scope; a user's own leaked key or malicious client is not (A7).

**How to read this table.** Rows are of four kinds: model guards (`LeanShieldedPool/Pool/Tx.lean`: deposit
106-110, transfer 141-160, withdraw 186-193), values the model builds by construction (commitments and
nullifiers as hash images), state updates (T12, T13, W6, X2), and implementation obligations the model does
not state (D6, S1-S3, X1, W10, G1; [SPEC-MAP.md](SPEC-MAP.md) simplifications 7 and 15 and the omitted
proof system, simplification 1). Each row names the enforcing layer, the evidence today and its status.
Trusted components common to many rows are A11; a row's "Proved" is always within A11. Row ids (D1 to
D6, T1 to T13, W1 to W10, X1 to X3, G1, S1 to S3) and the ids of conditions and assumptions (C1, A1 to
A13) are this board's own.

See [Why not green](#why-not-green) for each assumed row's blocker and next step.

Status words:
- **Proved:** machine-checked in full within the named formal domain (a Lean proof over the extracted
  circuit or model, a complete symbolic check of loop-free code, or an exact rebuild). It never means
  deployment safety by itself.
- **Proved\*:** the Kontrol property is machine-checked over its symbolic domain, and a written EVM gas argument
  with Lean-checked arithmetic (the gas envelope, below) places every transaction under the EIP-7825 cap
  (2^24 gas) inside that domain. All other premises of the Kontrol rejection scope remain: canonical ABI
  calls, pins, mocks, keccak lemmas, gas not modelled. Not deployment safety. \* valid for transactions
  under the EIP-7825 gas cap (2^24); the below-2^30 conclusion survives any transaction gas limit under
  4 x 2^30 gas. Canonical ABI layout and the Kontrol rejection scope remain required (a cross-family review).
- **Partly proved:** machine checks cover only the stated parts of the rule.
- **Counting rule** (set after a cross-family challenge): a row counts green when its status starts with
  "Proved" or "Proved*". A row enforced by two layers (circuit and contract) counts green only when both
  layers are proved or Proved*. "Bounded" counts as partly proved.
- **Bounded:** machine-checked within stated bounds (small trees, one reached state, a hand copy).
- **Assumed (GROUP):** (since 2026-10-02) the full rule retains an explicitly assumed gap. Before the
  first semicolon, name its primary groups and gap. After it, summarize existing evidence as proved, bounded, or read.
  Every subclaim retains the limits in its evidence cell. These tags do not replace the full premise
  list. Reclassification adds no machine evidence. Count the whole row as assumed, even if a subclaim is proved
  (a cross-family review).
- **Read:** source reading and tests only.
- **Open:** not checked yet. **Running:** a check is in progress.
- **Assumed:** a named assumption; **Condition:** a deployment requirement.

Code: ethsystems/pocs `a04b8b3`, `pocs/private-payment/shielded-pool/`. Line numbers refer to
`contracts/src/ShieldedPool.sol` unless a file is named. Status as of 2026-10-02 (G1 restated), with later
row edits to 2026-10-13; the table as a whole was read by a cross-family review (FAIL, corrections applied).

**Kontrol rejection scope (`guards-stock` and `guards-patched`, first run 2026-10-01, a cross-family review).**
Both use canonical ABI calls, zero value, symbolic caller and pool storage, and earlier-guard premises.
Stock deposit/transfer byte lengths are 0..2^30. The patched runs of the four withdraw guards (zero
amount, amount limit, spent nullifier, unknown root) cover proof lengths below 2^64 (the patch deletes one
KEVM encoding assumption, `abi.md:456`). Pool slots 108/109 pin the mock verifier/registry; the reentrancy
slot pins 1. Code stays fixed; registry storage is symbolic. KEVM keccak assumptions and environment bounds
remain; gas computation is disabled. Exact selectors establish rejection and exclude the verifier marker.
Retained-state preservation follows from rollback. All 13 stock mutants fail; the patched zero-amount
mutant also fails (`contract-kontrol` adds the other three patched mutants).

**Byte-length envelope (a cross-family review).** Under EIP-7825 and EIP-7623, transaction data is at most
1,675,621 bytes, and the memory charge bounds each internal-call input and each backed decoded byte argument
by 2,941,344 bytes, below 2^30. [refinement/README.md](refinement/README.md) ("Gas arithmetic") gives the
written argument; `GasEnvelope.byte_envelope` and its lemmas check its arithmetic (`refinement/scripts/check.sh`).
A gas-starved call can fail before its guard; gas stays unmodelled in the Kontrol rejection scope.

### Blocker groups

Primary counts: I insertion/composition 6; H provenance/record ordering 3; M membership 2; B proof/payload 2; X3 interpretation 1; token behavior 2. Total: **16** (G1 left the list on 2026-10-02: restated as owner-function behavior; the owner promise is in C1). Assumption rows are not counted again.

**I:** Existing deposit checks retain depth 0..3, bytes 0/65 and mocks. The insertion-loop K claims (`contract-kontrol` `insert-loop`) supply scoped loop/post-loop effects, not whole calls. `poseidon-frame` (`contract-kontrol`) permits a fixed function H for canonical 68-byte delegatecalls, fresh memory, sufficient gas and call depth. Reprove over H. Establish entry conditions, caller frames and composition. The `insert-loop` run `controls` supplies feasible concrete controls; the withdrawn K terminals do not become proofs. `poseidon-frame` proves neither Noir equality nor nonzero outputs.

**H:** T1/W1 need constructor, rollback, NoSetVerifier, ValidRootsFresh and TreeAppend instantiated universally. The withdraw corollary also needs WithdrawPost. `refinement` uses free hash outputs; `ring-funding` uses a keccak stub. T13 needs final-record call ordering at every depth. Exact retention for zero and repeated roots belongs separately to the Yul retention results (not in this repository); do not exclude them through A9b alone (the cross-family challenge that set the counting rule).

**M:** Membership needs model-root equality, nonzero inputs and bad-event exclusion. A9b covers collisions, commitment/node equalities and paths hashing to zero; Noir/Solidity hash equality remains unproved. Its computational premises are weaker than TreeHyp.no_bad. T3 also retains the ballast depth exemption and spec question.

**B:** The public-inputs runs fix empty deposit/transfer proofs; payloads and withdraw proofs are symbolic below 2^64. Scalars/storage are symbolic except pins; caller/funder, code and addresses are fixed. Canonical ABI, zero value, mocks, KEVM assumptions and unmodelled gas remain. Checks observe decoded mock bodies; attempted-call coverage also uses source reasoning. Finish joint proofs or check an independence argument. The fixed-token run supplies the scoped withdraw component (2026-10-06); caller/token, decoder, and production-call limits remain.

The fixed-token run uses fixed caller/token, recording mocks, the pins of the Kontrol rejection scope and canonical proof lengths below 2^64. It proves calls and ordering, not token movement. Earlier callback checks retain bytes 0/65.

No primary blocker requires changed UPSTREAM BEHAVIOR. The T3 SPEC QUESTION is secondary. ### What can never be green, and why

An unconditional deployment claim cannot follow from these proofs. Arbitrary tokens need not obey A10, including exact amounts, insufficient-balance rejection and no fees, rebases or outside debits. Additions and upgrades must preserve those properties. A1 assumes no commitment or derived-key collisions in the history. Cryptographic hardness and secret keys remain premises. Trusted tools remain under A11, including patched Lampe, KEVM/Kontrol, Halmos and the compilation chain.

Deployment facts need external checks: pinned runtime code, addresses, library links, verifier slot order, build settings, mocks disabled and no verifier swaps. C1 also requires transaction gas below 4 x 2^30 for Proved*. When the board was frozen, no deployment beyond a local test chain existed; [deployment/](deployment/README.md) now checks the Sepolia deployment at one block.

### What is possible but expensive

X3 can connect actual execution to the model. It needs universal posts, circuit interpretation, extraction, tree correspondence, token effects and rollback. Events remain open too. The conditional composition preserves money conclusions without RootsNonzero. Both routes need OwnerCallbackFree and CryptoHyp; `refineP_run` needs TreeHyp, while `refinePL_run` needs PathFacts and PathTreeHyp. Budget days to weeks; bounded component checks cannot supply those universal premises.
